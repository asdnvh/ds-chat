## 2. 为什么选 WebView 套壳

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **WebView + 内置 dist（本次采用）** | 零改网页代码、功能 100% 保留、离线可用、1 天可交付、后续可跟随上游升级 | 首屏略慢于原生；个别浏览器 API 需原生补桥 | ✅ 采用 |
| Capacitor / Cordova 套壳 | 生态插件多 | 引入 npm/构建链，仍需自己写下载/权限插件，收益不明显 | 可选替代 |
| TWA（Trusted Web Activity） | 最接近浏览器 | 必须把站点部署到 https 并做 Digital Asset Links，离线不可用，且需 Chrome | ❌ 不符合"离线 APK"预期 |
| Kotlin/Compose 原生重写 | 体验最好、体积最小可控 | 需重写 Markdown、KaTeX、Mermaid、流式 SSE、IndexedDB 迁移、语音等，工作量以周计 | 后续可选（见 §7.3） |

## 3. 关键技术决策

### 3.1 页面来源：不能用 `file://`

`file://` 页面的来源（origin）是 opaque，会导致：

- `localStorage` / `IndexedDB` 在部分 WebView 版本不可用 → **会话与 API Key 无法持久化**；
- `window.isSecureContext === false` → `getUserMedia`（语音输入）直接禁用；
- 跨域请求 `Origin: null`，服务端 CORS 可能拒绝。

因此工程实现了一个 40 行的 `AssetServer`：把 `src/main/assets/` 通过虚拟域名
`https://appassets.androidplatform.net/` 暴露给 WebView（`shouldInterceptRequest` 拦截，不产生真实网络请求）。
页面因此是**正常的安全上下文**，与在线版行为一致。同理，`getUserMedia`、`AudioContext`、`Clipboard` 都可正常使用。

> 与 AndroidX `WebViewAssetLoader` 等价，但本工程不引入任何 AndroidX 依赖，APK 更小、构建更快。

### 3.2 CORS：已实测放行（关键风险解除）

网页会直接跨域请求 `https://api.deepseek.com`（自定义头 `x-api-key`、`anthropic-beta`，multipart 上传，SSE 流）。
实测该服务对 `Origin: https://appassets.androidplatform.net` 的预检请求返回：

```
HTTP/1.1 200 OK
access-control-allow-origin: https://appassets.androidplatform.net
access-control-allow-methods: POST
access-control-allow-headers: x-api-key,content-type,accept,anthropic-beta
access-control-allow-credentials: true
```

即**服务端回显 Origin，不限制来源域名**，APK 内 WebView 直连 API 可行，无需自建代理。

### 3.3 原生能力补齐清单

| 网页依赖的浏览器能力 | 在 App 中缺失/受限 | 本工程实现 | 状态 |
|---|---|---|---|
| `<input type=file multiple>` 上传附件、导入历史 ZIP | WebView 不弹选择器 | `WebChromeClient.onShowFileChooser` → `ACTION_OPEN_DOCUMENT`（支持多选、按 accept 过滤 MIME） | ✅ |
| `URL.createObjectURL` + `<a download>` 导出历史 ZIP | WebView 的 DownloadListener 拿不到 blob 内容 | `DownloadListener` → 注入 JS 把 blob 转 base64 → `@JavascriptInterface` 保存到「下载/DSChat」 | ✅ |
| `getUserMedia` 麦克风（语音输入） | 需运行时权限 + `onPermissionRequest` | `onPermissionRequest` + `RECORD_AUDIO` 运行时申请 → 授权后 `request.grant()` | ✅ |
| `window.open` / `target=_blank` 外链（引用、Markdown 链接） | 无浏览器标签页 | `onCreateWindow` 用 1×1 临时 WebView 捕获目标 URL → 交给系统浏览器打开；不离开 App | ✅ |
| `AudioContext` 朗读（TTS 裸 PCM 流） | 一般可用 | 关闭 `mediaPlaybackRequiresUserGesture`，提高可靠性 | ✅ |
| `navigator.clipboard` 复制 | 安全上下文+用户手势即可 | 无需额外处理（失败时网页自带 textarea 兜底） | ✅ |
| 深浅色主题 | 状态栏/导航栏颜色与图标明暗 | 注入脚本监听 `<meta name="theme-color">` → 原生同步系统栏颜色与图标 | ✅ |
| `blob:` 图片点开预览（`target=_blank`） | WebView 无法跨窗口打开 blob URL | 注入脚本：图片用内置全屏浮层预览，其它文件保存到下载目录 | ✅ |
| 返回键 | 网页无历史记录 | 有浮层先关浮层 → `canGoBack` 则后退 → 否则双击退出 | ✅ |
| 键盘 / 状态栏遮挡 | Android 15+ 强制边到边 | `setDecorFitsSystemWindows(false)` + 用 `WindowInsets` 给根布局加 padding（状态栏/导航栏/输入法） | ✅ |

### 3.4 安全加固

- `setAllowFileAccess(false)`、外链一律外部浏览器打开、禁止明文 HTTP（`usesCleartextTraffic=false`、`MIXED_CONTENT_NEVER_ALLOW`）；
- `allowBackup=false`：避免 API Key 随云备份/`adb backup` 泄露；
- 只申请 3 个权限（INTERNET / RECORD_AUDIO / 旧系统写存储），无后台服务、无自启、无第三方 SDK；
- JS 桥接对象仅暴露 5 个方法（保存下载、主题色、浮层状态、日志、Toast），WebView 不加载任何外部页面，桥接面即可信；
- 网络出口与网页一致：只有 `api.deepseek.com`（审计已确认网页无其它外部请求）。

```
android/
├── gradlew / gradlew.bat / gradle/wrapper/       # Gradle 9.6.0 wrapper（已配置国内可用的发行版缓存复用）

└── app/
    ├── build.gradle.kts                          # compileSdk 37 / minSdk 26 / targetSdk 37
    ├── proguard-rules.pro
    ├── src/main/AndroidManifest.xml
    ├── src/main/assets/                          # 官方 dist 原样（153 文件）+ inject.js
    └── src/main/java/com/dschat/android/
        ├── MainActivity.java                     # WebView 宿主、权限、外链、弹窗、返回键、系统栏
        ├── AssetServer.java                      # assets → https://appassets.androidplatform.net 虚拟服务
```

## 5. 构建步骤

### 5.1 环境要求

- Android Studio（推荐，2026.x）或命令行构建：JDK 17+（AGP 9.5 要求）
- Android SDK：platform `android-37`、build-tools `36.0.0`（均已安装）
- 首次构建需联网下载 AGP/Kotlin 等插件依赖（可用 `GRADLE_USER_HOME` 指定 Gradle 缓存目录）

### 5.2 命令行构建

```powershell
cd android
# 按本机实际路径修改（Android Studio 默认安装位置）
$env:JAVA_HOME    = "C:\Program Files\Android\Android Studio\jbr"
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
.\gradlew.bat assembleDebug      # 产物：app\build\outputs\apk\debug\app-debug.apk
.\gradlew.bat assembleRelease    # 产物：app\build\outputs\apk\release\app-release.apk
```

### 5.3 Android Studio 构建

1. `File → Open` 选择 `android` 目录（不是 `app`）；
2. 等待 Gradle Sync 完成（`local.properties` 已指向 `E:/Android/Sdk`）；
3. `Build → Build Bundle(s)/APK(s) → Build APK(s)`；
4. 直接运行到手机：`Run → Run 'app'`（手机需开 USB 调试）。

### 5.4 安装到手机

```powershell
# 手机开启「USB 调试」并授权后
adb install -r "DSChat-0.1.1-debug.apk"
# 或把 APK 拷到手机，用文件管理器点击安装（需允许「安装未知应用」）
```

首次启动会弹出设置页要求填 API Key（网页原有逻辑）；Key 只存开发机 WebView 的 localStorage。

### 5.5 更换应用名 / 包名 / 图标

- 显示名：`app/src/main/res/values/strings.xml` 的 `app_name`
- 包名：`app/build.gradle.kts` 的 `namespace` 与 `applicationId`（两处都要改，且安装后无法与旧包共存）
- 图标：`res/drawable/ic_launcher_foreground.xml` + `res/values/colors.xml`（自适应图标，无需多套 PNG）
- 更换 API 地址：需要重新构建网页产物，见 §7.4

### 5.6 正式签名（已配置完成）

本工程已生成并配置项目自有的正式签名，`.\gradlew.bat assembleRelease` 产出的就是正式签名包：

- keystore：`android/keystore/dschat-release.jks`（PKCS12，RSA 4096，有效期 30 年）
- 配置：`android/keystore.properties`（`storeFile` / `storePassword` / `keyAlias=dschat` / `keyPassword`）
- 证书 DN：`CN=DS Chat, O=DS Chat Unofficial Build, C=CN`
- 证书 SHA-256：`c31b47887c23aa3bd3e83117ca814bd6448027f9afd8aa86631ae267eaeb9a61`

> ⚠️ `android/keystore.properties`、`android/keystore/` 已在 `android/.gitignore` 中排除，**不要提交、不要外发**。
> 备份副本（含密码与备份/升级/改密说明）：`签名材料-请勿分享/`。
> keystore 或密码丢失后，已安装用户将无法覆盖升级（只能卸载重装，聊天记录会丢）。

发新版本时：把 `app/build.gradle.kts` 的 `versionCode` +1、`versionName` 改为新版本号，保持同一 keystore 重新 `assembleRelease` 即可覆盖升级。
若更换自定义签名：在 `keystore.properties` 写 `storeFile=xxx.jks`、`storePassword`、`keyAlias`、`keyPassword` 即可（未配置时回退 debug 签名）。

### 6.1 关于开发机模拟器

开发机 `emulator -accel-check` 返回「Android Emulator hypervisor driver is not installed」，`HypervisorPresent=False`，

## 7. 已知限制与后续改进

### 7.1 已知限制（不影响主流程）

1. **blob 图片预览**：点开本地附件原图时，WebView 无法像浏览器那样在新窗口打开 `blob:` URL。当前实现为：图片用内置全屏浮层预览（点击/返回键关闭），非图片文件保存到「下载/DSChat」。
2. **历史导出大小**：导出 ZIP 走 base64 经 JS 桥接传给原生，聊天记录特别大（含多张大图、几十 MB）时会占用较多内存；普通使用无感。后续可改为原生拦截 `blob:` 由 WebView DevTools 协议读取，或改写导出链路。
3. **朗读（TTS）**：依赖 `AudioContext` 播放 24 kHz PCM，Android WebView 通常可用；但不同厂商 WebView 对非默认采样率支持略有差异，若无声可改用原生 `AudioTrack` 播放（需扩展桥接）。
4. **语音输入**：使用 `ScriptProcessorNode`（已废弃 API），现代 WebView 仍支持；若未来 WebView 移除该 API，需要上游改用 AudioWorklet 或原生录音桥接。
5. **API Key 明文**：沿用网页原有设计，存于 WebView localStorage（应用私有目录，未 root 的机器上其他应用无法读取）。如需更强保护可接入 Android Keystore 加密存储（需改网页代码）。
6. **外部链接**：一律交给系统浏览器，不会在 App 内打开；这是刻意的安全/一致性选择。

### 7.4 更换 API 地址的办法

`dist` 内的 API 地址是构建期注入的常量（`rspack.config.ts` 的 `createConfig({ apiOrigin })`）。若要用自建/代理地址：

```powershell
cd <源码目录>
# 修改 rspack.config.ts 默认值，或改用 createConfig({ apiOrigin: 'https://your.api' })
pnpm install --frozen-lockfile
pnpm build
# 用新的 dist 覆盖 android/app/src/main/assets/（保留 inject.js）
# 然后重新构建 APK
```

注意：自建地址同样需要正确返回 CORS 头（`Access-Control-Allow-Origin` 回显或允许
`https://appassets.androidplatform.net`）。

## 8. 风险提示（移植后仍需你确认的事）

1. **API Key 与费用**：App 直连 DeepSeek 官方 API，聊天/语音/上传都会产生账户费用；Key 泄露风险由用户自行承担（开发机存储，无云端）。
2. **接口兼容性**：本项目使用 Anthropic 兼容 Messages/Files API 与 `/v1/tools/asr|tts`、搜索、链接读取、`latest_reminder` 等扩展能力，服务端能力变化可能影响部分功能（与在线版同一风险）。
3. **厂商 WebView 差异**：页面 CSS 使用了 `100dvh`（Chromium 108+），且构建目标为 `chrome >= 105`，因此建议 Android System WebView ≥ 108（Play 商店可更新）。minSdk 26 只是系统下限，实际建议 Android 10+ 且 WebView 保持最新。
4. **未在真机实测**：开发机模拟器无硬件加速，端到端真机验证需要你用手机确认（聊天、上传、语音、导出、深色主题、键盘遮挡）。
