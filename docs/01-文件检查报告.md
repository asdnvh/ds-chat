- `sessions`（当前会话全文，含消息）
- `sessionSummaries`（列表摘要，含 `fileIds` 多值索引）
- `files`（附件**原始 Blob**，按本地 id 去重）
- `sessionsStaging` / `filesStaging`（历史导入事务暂存）

**风险说明（必须写进移植文档）**：

1. API Key 以**明文**存于 localStorage，没有加密、没有 Keystore、没有过期策略。任何能读到 WebView 数据目录的进程（root、备份导出、`adb backup`、恶意 App 共享同 origin 的 XSS、以及 WebView 调试）都能拿到 Key。这是应用自身设计（纯前端 demo 的常见取舍），**不是文件被篡改**。
2. 会话与附件同样明文存 IndexedDB，包括用户上传的原始文件（图片等）。
3. "导出所有历史对话"明确**不包含 API Key**（`exportArchive` 只写 manifest/session/index/图片），设计正确。
4. "删除所有对话"会清空会话/附件/草稿，但**保留 API Key 与设置**（README 已说明），卸载/清数据才会清除。
5. 隐私数据流：消息文本、附件、录音（WAV→ASR）、朗读文本（TTS）都会发往 `api.deepseek.com`；`location` 设置在**本版本代码中仅本地保存与展示，未被写入请求体**（已检索 `store.ts`/`reply.ts`/`client.ts` 等，未见消费点；如需 100% 确认可运行期抓包复核）。

### 6.7 网络 / CORS 要求

- 应用是**纯前端直连**：浏览器（或 WebView）直接向 `https://api.deepseek.com` 发 `fetch`（含 multipart 上传、`text/event-stream` 流式响应、PCM 音频流）。

## 8. 风险与建议（针对 APK 移植）

> 再次强调：以下**都不是"文件有问题"**，而是移植和分发时需要主动处理的事项。

### 8.1 优先级 P0（不处理，应用可能直接不可用）

1. **不要用 `file://` 加载页面。**
   `file://` 会导致：CORS `Origin: null` 被拒、`localStorage`/`IndexedDB` 受限、`getUserMedia`/`navigator.clipboard` 因非安全上下文失效。
   **建议**：`WebViewAssetLoader` + `https://appassets.androidplatform.net/assets/index.html`（origin 为 https，安全上下文成立，存储可用）。
2. **验证 `api.deepseek.com` 的 CORS 是否接受该 Origin。**
   官方 demo 在 `github.io` 域下可用，但自定义 `appassets.androidplatform.net` 是否被放行**必须实测**（发一个 `fetch('https://api.deepseek.com/models')` 看响应头）。
   若被拒：只能改架构——`shouldInterceptRequest` 拦截 `https://api.deepseek.com/*` 由原生代发（需自己处理 SSE 流式转发与证书校验），或在自有域名做反向代理。**这是本移植最大的技术不确定性，建议最优先做 PoC。**
3. **实现 WebView 原生桥接的 5 个回调**：
   - `WebChromeClient.onPermissionRequest` → 麦克风（录音）
   - `WebChromeClient.onShowFileChooser` → 上传附件/导入历史
   - `WebViewClient.shouldOverrideUrlLoading` → `target=_blank` 外链、充值/文档链接走系统浏览器
   - `DownloadListener` → 导出 ZIP（`blob:` URL 需 JS 取字节后交给原生保存）
   - `setSupportMultipleWindows(false)` + `setJavaScriptCanOpenWindowsAutomatically(false)`

### 8.2 优先级 P1（安全/隐私，建议处理）

4. **API Key 明文存储**：WebView 数据目录里的 localStorage 存着明文 Key。
   - 至少：`android:allowBackup="false"`（或用 `dataExtractionRules` 排除 WebView 数据），避免云端备份/`adb backup` 泄露；
   - 更好：Key 由原生层用 Android Keystore 加密后再交给前端（或注入 `window.__API_KEY__`，前端只在内存使用），前端代码需小改 `services/settings.ts`；
   - 注意：即使加密，XSS/调试仍可能拿到运行时 Key；不要在 Release 包开 `WebView.setWebContentsDebuggingEnabled(true)`。
5. **补安全响应头/策略**（静态包自身没有）：WebView 侧注入 CSP，例如
   `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; connect-src https://api.deepseek.com; font-src 'self'; object-src 'none'; base-uri 'none'`（需实测是否与 KaTeX/Mermaid 内联样式冲突，`unsafe-inline` 大概率需要）。
6. **关闭不必要的 WebView 能力**：`setAllowFileAccess(false)`、`setAllowContentAccess(false)`、`setAllowUniversalAccessFromFileURLs(false)`、`setDomStorageEnabled(true)`（这个要开）、禁用 `mixed content`。
7. **分发合规**：保留 `dist/LICENSE` + 补第三方声明（§5.3），建议在"设置→关于"里放"开源许可"入口。

### 8.3 优先级 P2（体验/兼容）

8. **WebView 版本门槛**：构建目标是 `chrome >= 105`；建议要求 Android System WebView ≥ 110（或最低 ≥ 105），并在启动时检测 `navigator.userAgent` 里的 Chrome 版本给出提示。Android 7/8 老设备上 WebView 可能远低于 105，`ReadableStream` 流式/`visualViewport`/深色模式行为可能有差异。
9. **键盘避让**：`adjustResize` + `visualViewport` 组合在 Android 上表现与 iOS 不同，输入框可能被键盘遮挡，需要实测。
10. **深色模式**：应用自带 `prefers-color-scheme` + 主题切换；WebView 若强制深色（`ForceDark`）会二次反色，建议禁用算法反色，让页面自己控制。
11. **音频焦点 / 蓝牙耳机**：TTS 播放走 `AudioContext`，需申请音频焦点（`AudioManager.requestAudioFocus`），否则可能与其他 App 混音或被暂停。
12. **构建可复现性**：Windows 下 `pnpm build` 脚本不可用（POSIX 写法），需改为 `cross-env NODE_ENV=production rspack build` 或用 `rimraf`；本审计已给出等价命令（§4.1）。锁定 `node 24.x + pnpm 11.x` + `pnpm-lock.yaml` 可 100% 复现 dist。
13. **大文件/长会话性能**：单 JS `main.js` 474,903 B（约 464 KiB）、最大异步 chunk 469,341 B（约 458 KiB，mermaid），首屏后按需加载；4.19 MiB 资源打进 APK 体积可控。

### 8.4 明确"没有发现"的问题（可放心）

- 无后门、无远程代码加载、无隐藏网络请求、无数据回传第三方、无键盘记录/剪贴板窃取、无设备指纹采集。
- 无硬编码密钥、无调试后门、无 `eval`。
- 与官方发布物逐字节一致，源码可完整重建出 dist。
